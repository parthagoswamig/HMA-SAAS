  □ Both URLs configured:

PART 3: VERCEL SETUP
================================================================================

□ VERCEL ACCOUNT
  --------------
  □ Vercel account created
  □ Vercel CLI installed: npm install -g vercel
  □ Logged in to Vercel: vercel login
  □ Git repository connected (optional but recommended)

□ BACKEND PROJECT (API)
  ---------------------
  □ Create new project: cd apps/api && vercel
  □ Link to existing project (if redeploying)
  □ Configure environment variables in Vercel dashboard:

    REQUIRED:
    □ NODE_ENV=production
    □ DATABASE_URL=postgresql://postgres.[PROJECT]:[PASS]@aws-0-[REGION].pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=1
    □ DIRECT_DATABASE_URL=postgresql://postgres.[PROJECT]:[PASS]@aws-0-[REGION].pooler.supabase.com:5432/postgres
    □ JWT_SECRET=[64-char-random-string]
    □ JWT_ACCESS_SECRET=[32-char-random-string]
    □ JWT_REFRESH_SECRET=[32-char-random-string]
    □ JWT_ACCESS_EXPIRATION=15m
    □ JWT_REFRESH_EXPIRATION=7d
    □ CORS_ORIGINS=https://your-frontend.vercel.app
    □ FRONTEND_URL=https://your-frontend.vercel.app
    □ SUPABASE_URL=https://[PROJECT-ID].supabase.co
    □ SUPABASE_ANON_KEY=[your-anon-key]
    □ SUPABASE_SERVICE_ROLE_KEY=[your-service-role-key]
    □ VERCEL=1

    OPTIONAL (if using payment gateways):
    □ STRIPE_SECRET_KEY=sk_live_xxx
    □ STRIPE_PUBLISHABLE_KEY=pk_live_xxx
    □ STRIPE_WEBHOOK_SECRET=whsec_xxx
    □ RAZORPAY_KEY_ID=rzp_live_xxx
    □ RAZORPAY_KEY_SECRET=xxx
    □ RAZORPAY_WEBHOOK_SECRET=xxx

    OPTIONAL (error tracking):
    □ SENTRY_DSN=https://xxx@sentry.io/xxx

  □ Deploy to preview: vercel
  □ Test preview deployment
  □ Deploy to production: vercel --prod
  □ Note production URL: https://your-api.vercel.app

□ FRONTEND PROJECT (WEB)
  ----------------------
  □ Create new project: cd apps/web && vercel
  □ Link to existing project (if redeploying)
  □ Configure environment variables in Vercel dashboard:

    REQUIRED:
    □ NEXT_PUBLIC_API_URL=https://your-api.vercel.app
    □ NEXT_PUBLIC_SUPABASE_URL=https://[PROJECT-ID].supabase.co
    □ NEXT_PUBLIC_SUPABASE_ANON_KEY=[your-anon-key]
    □ NEXT_PUBLIC_APP_ENV=production

  □ Deploy to preview: vercel
  □ Test preview deployment
  □ Deploy to production: vercel --prod
  □ Note production URL: https://your-frontend.vercel.app

□ UPDATE CORS
  -----------
  □ Update backend CORS_ORIGINS with actual frontend URL
  □ Redeploy backend if CORS was updated

PART 4: POST-DEPLOYMENT VERIFICATION
================================================================================

□ BACKEND API TESTS
  -----------------
  □ Health check: curl https://your-api.vercel.app/health
    Expected: {"status":"ok","timestamp":"...","uptime":...}
  
  □ Root endpoint: curl https://your-api.vercel.app/
    Expected: {"name":"HMS SaaS API","version":"1.0.0","status":"running"}
  
  □ Register user: POST /auth/register
    {
      "email": "test@example.com",
      "password": "Test123!@#",
      "firstName": "Test",
      "lastName": "User",
      "tenantSlug": "test-hospital"
    }
    Expected: 201 Created with user data
  
  □ Login: POST /auth/login
    {
      "email": "test@example.com",
      "password": "Test123!@#"
    }
    Expected: 200 OK with accessToken and refreshToken
  
  □ Protected endpoint: GET /patients (with Authorization header)
    Expected: 200 OK with patients list or empty array

  --------------
  □ Homepage loads: https://your-frontend.vercel.app
  □ Login page loads: /login

  □ Protected routes redirect to login when not authenticated
  □ Logout works
  □ No console errors in browser
  □ No 404 errors in Network tab

□ INTEGRATION TESTS

    2. Login
    3. Navigate to dashboard

PART 6: SECURITY CHECKLIST
================================================================================

□ AUTHENTICATION & AUTHORIZATION
  ------------------------------
  □ JWT secrets are strong (64+ characters)
  □ JWT expiration times are reasonable
  □ Refresh tokens work correctly
  □ Password hashing uses bcrypt
  □ RBAC permissions enforced on backend
  □ Protected routes require authentication
  □ Tenant isolation works correctly

□ API SECURITY
  ------------
  □ CORS configured correctly
  □ Rate limiting enabled
  □ Input validation on all endpoints
  □ SQL injection prevention (Prisma handles this)
  □ XSS prevention (React handles this)
  □ CSRF protection (for forms)
  □ Sensitive data not logged
  □ Error messages don't leak information

□ FRONTEND SECURITY
  -----------------
  □ Security headers configured (in next.config.js)
  □ No sensitive data in localStorage (except tokens)
  □ API keys not exposed in client code
  □ Environment variables use NEXT_PUBLIC_ prefix only when needed
  □ No console.log in production code
  □ Dependencies up to date (npm audit)

□ DATABASE SECURITY
  -----------------
  □ Database password is strong
  □ Connection uses SSL (Supabase default)
  □ Row Level Security enabled (if using Supabase Auth)
  □ Backup strategy in place
  □ No direct database access from frontend

□ INFRASTRUCTURE SECURITY
  -----------------------
  □ Vercel environment variables are encrypted
  □ No secrets in git repository
  □ .env files in .gitignore
  □ Production and staging environments separated
  □ Access logs enabled
  □ Two-factor authentication enabled on Vercel

TROUBLESHOOTING QUICK REFERENCE
================================================================================

ISSUE: Deployment fails
SOLUTION: Check Vercel build logs, verify all dependencies in package.json

ISSUE: Database connection errors
SOLUTION: Verify DATABASE_URL uses pgBouncer (port 6543), check Supabase status

ISSUE: CORS errors
SOLUTION: Add frontend URL to CORS_ORIGINS, verify in Vercel environment variables

ISSUE: JWT errors
SOLUTION: Verify JWT_SECRET matches, check token expiration, clear localStorage

ISSUE: Cold start timeouts
SOLUTION: Increase timeout in vercel.json, optimize Prisma initialization

ISSUE: High costs
SOLUTION: Review bandwidth usage, optimize images, implement caching
