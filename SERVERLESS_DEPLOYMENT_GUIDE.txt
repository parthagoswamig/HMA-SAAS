HMS SAAS - SERVERLESS DEPLOYMENT GUIDE (Vercel + Supabase)
================================================================================

This guide covers the complete serverless conversion and deployment process
for the HMS SaaS monorepo on Vercel + Supabase.

================================================================================
PART 1: WHAT CHANGED
================================================================================

1. BACKEND (NestJS) SERVERLESS CONVERSION
   ----------------------------------------
   - Created /apps/api/api/index.ts - Vercel serverless entry point
   - Updated /apps/api/vercel.json - Vercel deployment configuration
   - Modified CustomPrismaService - Lazy connection for serverless
   - Updated Prisma schema - Added directUrl for migrations
   - Optimized connection pooling - connection_limit=1 for serverless
   - Added express adapter for Vercel Functions compatibility

2. PRISMA + SUPABASE OPTIMIZATION
   --------------------------------
   - DATABASE_URL: Uses pgBouncer pooler (port 6543) for serverless functions
   - DIRECT_DATABASE_URL: Direct connection (port 5432) for migrations
   - Connection pooling: Minimal connections (limit=1) per function instance
   - Lazy connection: Connects on first query, not on module init
   - Error handling: Graceful degradation if DB unavailable

3. ENVIRONMENT VARIABLES
   ----------------------
   - Created .env.serverless template with production settings
   - Separated pooled vs direct database URLs
   - Added VERCEL=1 flag for serverless detection
   - Configured for Singapore region (sin1)

4. BUILD CONFIGURATION
   --------------------
   - Root vercel.json: Frontend deployment config
   - apps/api/vercel.json: Backend API deployment config
   - Updated package.json: Added vercel-build script
   - Prisma generation: Runs during build phase

PART 2: DEPLOYMENT INSTRUCTIONS
================================================================================

PREREQUISITES
-------------
1. Vercel account (https://vercel.com)
2. Supabase project (https://supabase.com)
3. Node.js 20+ installed locally
4. Git repository connected to Vercel

STEP 1: SETUP SUPABASE DATABASE
--------------------------------
1. Go to your Supabase project dashboard
2. Navigate to Settings > Database
3. Copy the following connection strings:

   POOLED CONNECTION (for serverless):
   postgresql://postgres.[PROJECT-ID]:[PASSWORD]@aws-0-[REGION].pooler.supabase.com:6543/postgres?pgbouncer=true

   DIRECT CONNECTION (for migrations):
   postgresql://postgres.[PROJECT-ID]:[PASSWORD]@aws-0-[REGION].pooler.supabase.com:5432/postgres

4. Run migrations:
   cd apps/api
   export DIRECT_DATABASE_URL="your-direct-url"
   npm run prisma:migrate:deploy

STEP 2: DEPLOY BACKEND API TO VERCEL
-------------------------------------
1. Create new Vercel project for backend:
   vercel --cwd apps/api

2. Configure environment variables in Vercel dashboard:
   
   REQUIRED VARIABLES:
   -------------------
   NODE_ENV=production
   DATABASE_URL=postgresql://postgres.[PROJECT]:[PASS]@aws-0-[REGION].pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=1
   DIRECT_DATABASE_URL=postgresql://postgres.[PROJECT]:[PASS]@aws-0-[REGION].pooler.supabase.com:5432/postgres
   
   JWT_SECRET=[generate-64-char-random-string]
   JWT_ACCESS_SECRET=[generate-32-char-random-string]
   JWT_REFRESH_SECRET=[generate-32-char-random-string]
   JWT_ACCESS_EXPIRATION=15m
   JWT_REFRESH_EXPIRATION=7d
   
   CORS_ORIGINS=https://your-frontend.vercel.app
   FRONTEND_URL=https://your-frontend.vercel.app
   
   SUPABASE_URL=https://[PROJECT-ID].supabase.co
   SUPABASE_ANON_KEY=[your-anon-key]
   SUPABASE_SERVICE_ROLE_KEY=[your-service-role-key]
   
   VERCEL=1
   
   OPTIONAL (Payment Gateways):
   ----------------------------
   STRIPE_SECRET_KEY=sk_live_xxx
   RAZORPAY_KEY_ID=rzp_live_xxx
   RAZORPAY_KEY_SECRET=xxx

3. Deploy:
   cd apps/api
   vercel --prod

4. Note your API URL: https://your-api.vercel.app

STEP 3: DEPLOY FRONTEND TO VERCEL
----------------------------------
1. Create new Vercel project for frontend:
   vercel

2. Configure environment variables:
   
   NEXT_PUBLIC_API_URL=https://your-api.vercel.app
   NEXT_PUBLIC_SUPABASE_URL=https://[PROJECT-ID].supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=[your-anon-key]
   NEXT_PUBLIC_APP_ENV=production

3. Deploy:
   vercel --prod

4. Your frontend will be live at: https://your-frontend.vercel.app

STEP 4: VERIFY DEPLOYMENT
--------------------------
1. Test API health:
   curl https://your-api.vercel.app/health

2. Test frontend:
   Open https://your-frontend.vercel.app

3. Test authentication:
   - Register a new user
   - Login
   - Verify JWT tokens are working

4. Monitor Vercel logs:
   vercel logs [deployment-url]

PART 4: COST OPTIMIZATION & ALTERNATIVES
================================================================================

CURRENT SETUP: VERCEL + SUPABASE
---------------------------------
Monthly Costs (Estimated):
- Vercel Pro: $20/month (includes 100GB bandwidth, 1000 serverless hours)
- Supabase Pro: $25/month (8GB database, 50GB bandwidth, 100GB storage)
- Total: ~$45/month for production-ready setup

Pros:
✅ Zero DevOps - fully managed
✅ Auto-scaling - handles traffic spikes
✅ Global CDN - fast worldwide
✅ Built-in monitoring and logs
✅ Easy rollbacks and previews
✅ Excellent DX (developer experience)

Cons:
❌ Can get expensive at scale (bandwidth costs)
❌ Cold starts on serverless functions
❌ Limited control over infrastructure

ALTERNATIVE 1: VERCEL + NEON (Serverless Postgres)
---------------------------------------------------
Monthly Costs: ~$40/month
- Vercel Pro: $20/month
- Neon Pro: $19/month (auto-scaling, better cold start)

Pros:
✅ Better cold start performance than Supabase
✅ Auto-scaling database
✅ Branching for dev/staging
✅ Lower latency

Cons:
❌ No built-in auth (need to implement)
❌ Newer platform (less mature)

ALTERNATIVE 2: RAILWAY + SUPABASE
----------------------------------
Monthly Costs: ~$30/month
- Railway: $5-10/month (pay-as-you-go)
- Supabase Pro: $25/month

Pros:
✅ Cheaper than Vercel
✅ Traditional server (no cold starts)
✅ More control over infrastructure
✅ Better for long-running processes

Cons:
❌ Manual scaling required
❌ Less mature deployment pipeline
❌ No automatic preview deployments

ALTERNATIVE 3: SELF-HOSTED (AWS/DigitalOcean)
----------------------------------------------
Monthly Costs: ~$50-100/month
- EC2/Droplet: $20-40/month
- RDS/Managed DB: $30-60/month
- Load Balancer: $10/month

Pros:
✅ Full control
✅ No vendor lock-in
✅ Predictable costs at scale
✅ Can optimize for specific workload

Cons:
❌ Requires DevOps expertise
❌ Manual scaling and monitoring
❌ Security management responsibility
❌ Higher maintenance overhead

RECOMMENDATION FOR HMS SAAS
---------------------------
For MVP/Early Stage (< 1000 users):
→ Vercel + Supabase (current setup)
  Reason: Best DX, fastest to market, zero DevOps

For Growth Stage (1000-10000 users):
→ Vercel + Neon OR Railway + Supabase
  Reason: Better performance, lower costs

For Scale (10000+ users):
→ Self-hosted on AWS with RDS
  Reason: Full control, predictable costs, better margins

MONITORING
----------

   - Function execution time

2. Supabase Monitoring:

   - Setup Sentry (optional)
   - Add SENTRY_DSN to environment variables

MAINTENANCE TASKS
-----------------
1. Database Migrations:
   - Always use DIRECT_DATABASE_URL
   - Test in staging first
   - Run: npm run prisma:migrate:deploy

2. Prisma Client Updates:
   - Regenerate after schema changes
   - Run: npm run prisma:generate
   - Redeploy both frontend and backend

3. Security Updates:
   - Rotate JWT secrets quarterly
   - Update dependencies monthly
   - Review Vercel security logs

4. Performance Optimization:
   - Monitor cold start times
   - Optimize Prisma queries
   - Add database indexes as needed
   - Use Vercel Edge Functions for static content

PART 6: TROUBLESHOOTING
================================================================================

ISSUE: Cold Start Timeouts
---------------------------
Solution:
- Increase function timeout in vercel.json (max 30s for Pro)
- Optimize Prisma client initialization
- Use Vercel's "Keep Warm" feature (Pro plan)

ISSUE: Database Connection Errors
----------------------------------
Solution:
- Verify DATABASE_URL uses pgBouncer (port 6543)
- Check connection_limit=1 in URL
- Verify Supabase pooler is enabled
- Check Supabase connection limits

ISSUE: CORS Errors
-------------------
Solution:
- Add frontend URL to CORS_ORIGINS
- Verify credentials: true in CORS config
- Check Vercel environment variables
- Clear browser cache

ISSUE: JWT Token Errors
------------------------
Solution:
- Verify JWT_SECRET matches between deployments
- Check token expiration times
- Verify JWT_ACCESS_SECRET and JWT_REFRESH_SECRET
- Clear localStorage and re-login

ISSUE: Build Failures
----------------------
Solution:
- Check Vercel build logs
- Verify all dependencies in package.json
- Run prisma generate before build
- Check TypeScript errors locally first
